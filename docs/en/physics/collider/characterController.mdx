The [CharacterController](/apis/core/#CharacterController) is a special collider component designed specifically for handling character physics movement. It provides specialized movement algorithms and collision detection, capable of handling complex terrain like steps and slopes, making it particularly suitable for character control in first-person or third-person games.

## Differences from Rigidbody

While both the Character Controller and a [Rigidbody](/en/docs/physics/collider/rigidbody) can move objects, they have significant differences:

| Feature | Character Controller | Rigidbody |
|---------|---------------------|------------------|
| Movement Method | Direct displacement control via `move()` method | Movement through forces or velocity |
| Collision Response | Manual collision response, automatic step and slope handling | Physics-based collision response |
| Gravity Handling | Requires manual gravity implementation | Automatic scene gravity application |
| Shape | Inline capsule or box, selected by `geometry` | Any Collider components on its Entity and children |
| Use Cases | Character control, first/third-person games | Physics simulation, rigid body motion |

<Callout type="positive">
Recommendations:
- Use Character Controller when precise control over character movement and collision response is needed
- Use Rigidbody when realistic physics simulation is required
</Callout>

## Usage

1. Select the target entity and click the Add Component button in the inspector to add the CharacterController component.

<Image src="https://mdn.alipayobjects.com/huamei_3zduhr/afts/img/A*nEMXRKiqpy8AAAAAAAAAAAAAesJ_AQ/original" />

2. Choose the controller's `geometry` and set its size (`radius` and `height` for a capsule, `size` for a box) and `center` to match the character's appearance as closely as possible.

<Callout type="positive">
The Character Controller carries its own geometry instead of using other Collider components, and it is never owned by a Rigidbody. A capsule, the default, is recommended for characters.
</Callout>

3. Adjust the controller's properties according to your needs. The meaning and function of each property are explained below.

## Property Description

### Geometry
| Property | Description | Default |
|----------|-------------|---------|
| [**geometry**](/apis/core/#CharacterController-geometry) | `CharacterControllerGeometry.Capsule` (a capsule along `upDirection`) or `CharacterControllerGeometry.Box` (an axis-aligned box) | Capsule |
| [**radius**](/apis/core/#CharacterController-radius) | Capsule radius in the Entity's local space | 0.5 |
| [**height**](/apis/core/#CharacterController-height) | Total capsule height including both caps. The scaled height must exceed the scaled diameter. | 2 |
| [**size**](/apis/core/#CharacterController-size) | Box size in the Entity's local space | (1, 1, 1) |
| [**center**](/apis/core/#Collider-center) | Center of the geometry in the Entity's local space | (0, 0, 0) |

The geometry follows the Entity's world scale. `rotation` inherited from Collider does not apply to the controller.

### Properties Inherited from Collider
| Property | Description | Default |
|----------|-------------|---------|
| [**contactOffset**](/apis/core/#CharacterController-contactOffset) | Contact offset. Must be greater than 0; other values throw | 0.02 |
| [**collisionLayer**](/apis/core/#Collider-collisionLayer) | Collision layer of the controller | Layer.Layer0 |
| [**material**](/apis/core/#Collider-material) | Physics material, `null` for the shared default | null |
| [**isTrigger**](/apis/core/#CharacterController-isTrigger) | Always false; setting it to true throws | false |

### Specific Properties
| Property | Description | Default |
|----------|-------------|---------|
| [**detectCollisions**](/apis/core/#CharacterController-detectCollisions) | Lets incoming rigidbodies and other controllers collide with this controller. Setting it to `false` also disables trigger interactions. The controller's own `move()` still detects obstacles, and `isSceneQuery` still controls query visibility. | true |
| [**stepOffset**](/apis/core/#CharacterController-stepOffset) | Requested step height in world units. PhysX limits the effective step to the scaled height. The property retains the requested value. Finite negative values are clamped to 0. | 0.5 |
| [**climbingMode**](/apis/core/#CharacterController-climbingMode) | Capsule step behavior. `Easy` allows the rounded capsule to climb higher than `stepOffset`. `Constrained` limits that behavior. | Constrained |
| [**slopeLimit**](/apis/core/#CharacterController-slopeLimit) | Maximum slope angle (in degrees) the character can walk on.<ul><li>Surfaces steeper than this angle will be treated as unwalkable walls</li><li>Affects the character's climbing ability</li></ul> | 45° |
| [**nonWalkableMode**](/apis/core/#CharacterController-nonWalkableMode) | Defines how to handle unwalkable surfaces.<ul><li>PreventClimbing: Prevents the character from climbing unwalkable slopes but doesn't force other movements (default)</li><li>PreventClimbingAndForceSliding: Prevents the character from climbing unwalkable slopes and forces the character to slide down</li></ul> | PreventClimbing |
| [**upDirection**](/apis/core/#CharacterController-upDirection) | Defines the character's up direction. Default is (0, 1, 0), which means Y-axis up in world space. Affects movement and collision detection direction | (0, 1, 0) |

## Public Methods

| Method | Description |
|--------|-------------|
| [**move**](/apis/core/#CharacterController-move) | Move the character controller and write the result to the Entity's world position immediately. Returns a collision flag value indicating collision status, or 0 when the controller is not in a scene.<ul><li>displacement: Movement vector</li><li>minDist: Remaining distance at which the sweep stops, defaults to 0</li><li>elapsedTime: Seconds since the previous move, defaults to the scene's fixed timestep</li></ul> |
| [**getFootPosition(out)**](/apis/core/#CharacterController-getFootPosition) | Write the world position of the foot, including the contact offset. |
| [**setFootPosition(position)**](/apis/core/#CharacterController-setFootPosition) | Teleport the controller so its foot is at the given world position. |
| [**resize(height)**](/apis/core/#CharacterController-resize) | Set the local total height while keeping the foot in place. Check for clearance before growing the controller. |

Use `isGrounded` or `collisionFlags` to read the last move's contacts. Call `getVelocity(out)` to read its actual world-space velocity. Scene queries see the new pose in the same frame.

Pass a `ControllerMoveFilter` as the fourth argument to limit a single move. `layerMask` selects collision layers and `exclude` skips specific colliders, including other character controllers. The scene collision matrix and pair exclusions still apply.

Implement `onControllerColliderHit(hit)` on a script attached to the moving entity to receive sweep contacts. The callback runs after the entity's position is written and before `move` returns. A single move can report multiple contacts. Each hit identifies the collider and provides the world-space point, normal, direction, and length of the sweep segment. Copy any values you need to keep.

Use the hit data to apply a force or impulse to `hit.collider.attachedRigidbody` when implementing pushes. While grounded on a moving platform, `move` follows the support point as the platform translates or rotates. The entity retains its facing direction.

The scene's `physics.characterControllerOverlapRecovery` defaults to `true`. During movement, it lets controllers recover from overlaps with static colliders.

`getClosestPoint` is not supported by the Character Controller and returns -1.

### Collision Flags

The `move()` function returns a collision flag value that indicates the character controller's collision status with the environment. These flags can be detected using bitwise AND operations (&):

| Flag Name | Value | Description |
|-----------|-------|-------------|
| None | 0 | No collision occurred |
| Sides | 1 | Collided with sides |
| Up | 2 | Collided with the top (e.g., ceiling) |
| Down | 4 | Collided with the bottom (e.g., ground) |

## Script Usage

### Basic Configuration
```typescript
// A new controller uses capsule geometry.
const controller = entity.addComponent(CharacterController);
controller.radius = 0.5;
controller.height = 2;
controller.center = new Vector3(0, 1, 0);

// To use a box, configure its full size along the local axes.
// controller.geometry = CharacterControllerGeometry.Box;
// controller.size = new Vector3(1, 2, 1);

// Configure controller properties
controller.stepOffset = 0.5;      // Set step height
controller.slopeLimit = 45;       // Set maximum walkable slope angle
controller.upDirection = new Vector3(0, 1, 0); // Set upward direction
```

### Using the Move Function
```typescript
class CharacterMovement extends Script {
  private _controller: CharacterController;
  private readonly _displacement = new Vector3();
  private _verticalSpeed = 0;
  private _jumpRequested = false;

  onAwake() {
    this._controller = this.entity.getComponent(CharacterController);
  }

  onUpdate() {
    this._jumpRequested ||= this.engine.inputManager.isKeyDown(Keys.Space);
  }

  onPhysicsUpdate() {
    const input = this.engine.inputManager;
    const physics = this.scene.physics;
    const dt = physics.fixedTimeStep;
    const x = Number(input.isKeyHeldDown(Keys.KeyD)) - Number(input.isKeyHeldDown(Keys.KeyA));
    const z = Number(input.isKeyHeldDown(Keys.KeyW)) - Number(input.isKeyHeldDown(Keys.KeyS));
    const displacement = this._displacement.set(x, 0, z).normalize().scale(5 * dt);

    if (this._jumpRequested && this._controller.isGrounded) {
      this._verticalSpeed = 5;
    }
    this._jumpRequested = false;
    this._verticalSpeed += physics.gravity.y * dt;
    displacement.y = this._verticalSpeed * dt;

    const contacts = this._controller.move(displacement);
    if (contacts & (ControllerCollisionFlag.Down | ControllerCollisionFlag.Up)) {
      this._verticalSpeed = 0;
    }
  }
}
```

Usage example:
```typescript
const flags = controller.move(displacement, 0, deltaTime);

// Check if touching ground
if (flags & ControllerCollisionFlag.Down) {
    // Character is on ground
    this._isGrounded = true;
}

// Check if hitting ceiling
if (flags & ControllerCollisionFlag.Up) {
    // Character hit ceiling
    this._velocity.y = 0;
}

// Check if hitting wall
if (flags & ControllerCollisionFlag.Sides) {
    // Character hit wall
    this._handleWallCollision();
}

// Can check multiple flags simultaneously
if ((flags & ControllerCollisionFlag.Down) && 
    (flags & ControllerCollisionFlag.Sides)) {
    // Character is touching both ground and wall
}
```

### Slope/Step Walking

1. **Slope Walking**
```typescript
// Control walkable slope angle by setting slopeLimit
controller.slopeLimit = 60; // Allow steeper slopes

// Set how to handle unwalkable slopes
controller.nonWalkableMode = ControllerNonWalkableMode.PreventClimbingAndForceSliding; // Will slide down on too steep slopes
```

2. **Step Walking Adjustment**
```typescript
// Adjust stepOffset to control climbable step height
controller.stepOffset = 0.3; // Lower steps
controller.stepOffset = 0.5; // Higher steps
```

### Gravity Handling

The Character Controller itself doesn't include gravity handling; you need to implement gravity effects manually in scripts. Here's a complete gravity handling example:

```typescript
class CharacterMovement extends Script {
  private _controller: CharacterController;
  private _velocity = new Vector3();
  private _isGrounded = false;
  private _moveSpeed = 5;
  private _jumpForce = 5;
  private _gravity: Vector3;

  onAwake() {
    this._controller = this.entity.getComponent(CharacterController);
    this._gravity = this.scene.physics.gravity;
  }

  onUpdate(deltaTime: number) {
    const inputManager = this.engine.inputManager;

    // Get input
    const horizontal = inputManager.isKeyHeldDown(Keys.KeyA) ? -1 : inputManager.isKeyHeldDown(Keys.KeyD) ? 1 : 0;
    const vertical = inputManager.isKeyHeldDown(Keys.KeyS) ? -1 : inputManager.isKeyHeldDown(Keys.KeyW) ? 1 : 0;
    const jump = inputManager.isKeyDown(Keys.Space);

    // Calculate movement direction
    const moveDirection = new Vector3(horizontal, 0, vertical);
    moveDirection.normalize();

    // Apply movement speed
    this._velocity.x = moveDirection.x * this._moveSpeed;
    this._velocity.z = moveDirection.z * this._moveSpeed;

    // Apply gravity
    if (!this._isGrounded) {
      this._velocity.y += this._gravity.y * deltaTime;
    }

    // Handle jumping
    if (this._isGrounded && jump) {
      this._velocity.y = this._jumpForce;
      this._isGrounded = false;
    }

    // Execute movement
    const displacement = new Vector3();
    Vector3.scale(this._velocity, deltaTime, displacement);
    const collisionFlags = this._controller.move(displacement, 0, deltaTime);

    // Update ground status
    this._isGrounded = (collisionFlags & ControllerCollisionFlag.Down) !== 0;
    if (this._isGrounded) {
      this._velocity.y = 0;
    }
  }
}
```

## Limitations and Considerations

1. **Geometry**
   - The controller has exactly one inline capsule or box; other Collider components on the Entity are separate Colliders
   - A capsule is recommended for characters
   - The controller cannot be a trigger and does not support `getClosestPoint`

2. **Performance Considerations**
   - Each Character Controller consumes some physics calculation resources
   - It's recommended to control the number of Character Controllers in the scene
